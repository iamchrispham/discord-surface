PARTIAL — The decision rule changes, but evidence still constrains commitment. Proposed rule, not an operator-approved numerical budget: Go need not wait for optimized Node to fail today’s memory limit. It must demonstrate custody parity, bounded long-run growth, acceptable latency/CPU, and a concrete resource or deployment advantage worth the port. Measure actual Gateway/listener/helper multiplicity, not conductor count alone. Separate deployed-runtime measurements from cold builds and warm edit/test loops, including compiler, linker, SQLite, and test-child costs. If Go offers no meaningful combined advantage, stop and retain Node. If Go’s runtime overhead is the binding failure, investigate a small dependency-loaded Rust alternative before considering a second substantial port.
